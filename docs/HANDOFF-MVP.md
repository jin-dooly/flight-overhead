## 2. 작업별로 바뀐 것과 이유

### 2-1. 디자인 토큰과 지도 모양 (`4241194`)

**바뀐 파일:** `index.html`, `src/index.css`, `components/map/aircraftIcon.ts`, `components/map/MyLocationLayer.tsx`(새 파일), `components/map/MapViewSync.tsx`(새 파일), `lib/geo/distance.ts`(`boundsAround` 추가), `config.ts`

- **디자인 토큰:** 목업 스타일 가이드(Tokens)의 색을 `:root`의 CSS 변수(`--text`, `--accent`, `--warn-bg` …)로 옮겼습니다. 글꼴은 IBM Plex Sans KR / IBM Plex Mono를 Google Fonts에서 불러옵니다.
- **비행기 마커:** 목업의 비행기 실루엣(흰 테두리)으로 바꾸고 28px로 키웠습니다. 모양은 CSS 클래스로만 바뀝니다.
  - `is-highlighted`: 파란 원 + 파란 라벨 (선택했거나 카드에 보이는 가장 가까운 비행기)
  - `is-stale` / `is-outside` / `.is-offline` 안: 흐리게 (30초 미수신, 반경 밖, 서버 끊김)
  - 클래스를 바꾸는 함수 `setMarkerClass`만 두고, 색은 CSS가 정합니다. 마커를 다시 만들지 않으니 매 프레임 루프와 부딪치지 않습니다.
  - 회전에 `transition`을 넣지 않았습니다. 359도 → 1도로 바뀌면 반대로 한 바퀴 도는 것처럼 보이기 때문입니다.
- **반경 원:** 목업처럼 바깥 원은 점선, 안쪽 원은 실선, 원 위쪽에 "20km" 라벨. 내 위치 점은 흰 테두리와 연한 파란 그림자. 라벨은 비행기 마커보다 아래(`zIndexOffset -1000`)에 그려서 겹쳐도 비행기가 보입니다.
- **최소 줌 (`ZoomLimit`):** 기획서 결정 "반경 30km가 보이는 정도까지만 축소"를 구현했습니다.
  - `boundsAround(내 위치, 30km)`가 화면에 다 들어가는 줌을 Leaflet의 `getBoundsZoom`으로 계산해 `setMinZoom`에 넣습니다.
  - 고정값 대신 계산하는 이유: 화면 크기에 따라 필요한 줌이 다릅니다(폰 세로 약 9, 데스크톱 약 10). 창 크기가 바뀌면 다시 계산합니다.

### 2-2. 순수 함수와 테스트 (`7b2efec`)

**바뀐 파일:** `lib/format.ts`, `lib/mapStatus.ts`, `lib/nearby.ts`(모두 새 파일), `test/format.test.ts`, `test/nearby.test.ts`

화면에서 판단이 들어가는 부분을 React 밖의 순수 함수로 빼고 테스트했습니다(CLAUDE.md: 순수 함수는 Vitest로 검증).

- **`format.ts`:** 카드 값 표시
  - 고도: ft → m(10m 단위 반올림, 기압 고도라 그 이상 정밀하지 않음), 아래에 원래 ft
  - 속도: kt → km/h, 아래에 kt
  - 방향: 8방위 이름(북, 북동 …, 각 방위 ±22.5도), 아래에 각도
  - 거리: 100km 미만은 소수점 한 자리(목업 5.9, 13.1, 21.8)
  - 테스트에 목업 숫자를 그대로 넣었습니다(8,000 ft → 2,440 m, 250 kt → 463 km/h, 215° → 남서).
- **`mapStatus.ts` (`deriveDataStatus`):** 연결 상태와 데이터 신선도를 하나로 합칩니다.
  - 연결 중 / 재연결 중이면 그대로, 연결됐으면 `degraded`이거나 스냅샷이 20초보다 오래됐을 때 "데이터 지연"
  - 20초 기준: 정상 갱신 간격이 약 6초라 세 번 연속 못 받은 정도
  - 서버가 `degraded`를 보내지 않아도 데이터가 멈추면 지연으로 보는 이유: 서버가 살아 있어도 폴링이 멈추는 경우(예: 구독 직후 첫 조회 실패)를 사용자가 알 수 있게
- **`nearby.ts`:**
  - `splitByRadius`: 스냅샷을 내 위치 기준 반경 안(가까운 순)과 "반경 밖에서 가장 가까운 하나"로 나눔
  - `pickCardTarget`: 고른 비행기가 반경 안에 있으면 그 비행기, 아니면 가장 가까운 비행기

### 2-3. 지도 위 UI (`c7f7919`)

**바뀐 파일:** `pages/MapPage.tsx`(다시 작성), `components/mapUi/`(새 폴더: `TopBar`, `StatusBanner`, `AircraftSheet`, `MapControls`, `icons`, `mapUi.css`), `hooks/useMapData.ts`, `hooks/useNow.ts`, `hooks/useMediaQuery.ts`, `store/flights.ts`(`radiusKm`, `serverNow`), `components/map/AircraftLayer.tsx`(강조, 흐림)

**화면 구성 (목업 Main, MapSelected, MapEmpty, MapReconnecting, MapDelayed, MapDefaultLocation, MapDesktop)**

- 상단 칩: 위치("내 위치" / "인천공항" / "위치 확인 중"), "반경 20km · N대", 상태(실시간 / 연결 중 / 재연결 중 / 데이터 지연)
- 안내 띠: 겹치면 하나만. 순서는 연결 끊김 > 데이터 지연 > 위치 확인 중 > 기본 위치로 보는 중(다시 시도 버튼)
- 하단 카드
  - 선택 전: "가장 가까운 비행기" + "N초 전 기준"
  - 선택 후: "선택한 비행기" + 닫기(×) 버튼, 아래에 "기체 ID · N초 전 기준"
  - 편명이 없으면 기체 ID를 크게, 아래에 "편명 정보가 없어요"
  - 연결이 끊기면 값을 회색으로, 지연이면 "N초 전 기준"을 주황색으로
  - 반경 안이 비면 "지금 머리 위에는 비행기가 없어요" + 가장 가까운 비행기와 거리 + "반경 30km까지 넓히기"
  - 아직 데이터가 없으면 "비행기 정보를 받아 오는 중이에요" (Render가 잠들어 있으면 첫 접속이 1분 가까이 걸린다는 안내 포함)
- 오른쪽 아래: 내 위치 버튼(데스크톱은 확대/축소 버튼도), 왼쪽 아래: 출처
- 데스크톱(768px 이상): 칩과 카드를 왼쪽 위 380px 패널로

**핵심 구현**

- **1초마다 다시 그리는 범위를 작게:** "N초 전"과 카드의 거리는 1초마다 바뀌어야 합니다. `useDataStatus`(안에서 `useNow(1000)`)를 쓰는 작은 컴포넌트(`TopAndBanner`, `SheetWithStatus`)만 1초마다 다시 그려지고, 지도(`MapContainer`)와 마커는 영향을 받지 않습니다.
- **카드의 거리는 매초 예상 위치로:** 스냅샷 때 거리(최대 6초 전 위치)가 아니라 `predictPosition`으로 지금 위치를 예측해서 거리를 계산합니다. 지도 마커와 카드 숫자가 같은 기준으로 움직입니다.
- **강조와 흐림은 클래스로:** `AircraftLayer`에 `highlightHex`, `outsideHex`를 넘기면 해당 마커의 클래스만 바꿉니다. 30초 미수신 판단은 매 프레임 루프 안에서 하되, 값이 바뀔 때만 클래스를 바꿉니다.
- **선택 정리:** 고른 비행기가 반경 밖으로 나가거나 사라지면 `selectedHex`를 비웁니다. 나중에 다시 들어왔을 때 갑자기 선택돼 있지 않게 하려는 것입니다.
- **지도 위 UI의 클릭:** UI 전체 레이어는 `pointer-events: none`이라 빈 곳을 끌면 지도가 움직이고, 칩·카드·버튼만 클릭을 받습니다.
- **출처 표시:** Leaflet 기본 출처 표시는 오른쪽 아래라 폰에서 카드에 가려집니다. 기본 표시를 끄고 카드 바로 위에 직접 그렸습니다(OpenStreetMap 저작권 링크 포함).

### 2-4. "30초 동안 안 보인 비행기는 흐려지게 했다가 제거" 해석

- 마지막 위치를 받은 지 30초(`MAX_PREDICT_MS`)가 넘으면 흐리게 보여 줍니다. 같은 30초에 예측도 멈추므로, 흐린 비행기는 "멈춘 마지막 위치"라는 뜻이 됩니다.
- 제거는 서버 스냅샷에서 빠질 때 합니다. adsb.lol/adsb.fi는 오래 안 보인 기체를 응답에서 빼므로, 따로 타이머를 두지 않았습니다.

### 2-5. 배포 후 고친 것: 폰에서 지도 중심 (`4da9533`)

배포된 사이트를 폰 크기로 열어 보니, 카드가 화면 아래 약 3분의 1을 가려서 내 위치 근처 비행기가 카드 뒤에 숨었습니다.

## 3. 내린 결정 (작은 결정)

- 위치 칩은 동네 이름 대신 "내 위치". 동네 이름은 정확한 좌표를 외부 역지오코딩 서비스로 보내야 해서 "정확한 위치는 브라우저 밖으로 보내지 않음" 원칙과 맞지 않음.
- 연결 상태에 "연결 중"(회색, 회전 아이콘)을 추가. 앱을 처음 열 때는 아직 끊긴 게 아니라서 "재연결 중"은 맞지 않고, Render가 잠들어 있으면 이 상태가 1분 가까이 이어짐.
- "데이터 지연" 기준은 서버 `degraded` 또는 스냅샷이 20초보다 오래됨.
- 카드의 "N초 전 기준"은 스냅샷 시각이 아니라 그 비행기의 위치 시각(`seenAt`). 비행기마다 마지막 수신 시각이 달라서, 그 비행기 정보가 얼마나 오래됐는지가 더 정확함.
- 반경 넓히기는 20km → 30km 한 단계. 30km는 서버 조회 반경(17해리 ≈ 31km)과 최소 줌에 맞춘 값. 페이지를 새로 열면 20km로 돌아감.
- 반경 안이 비었을 때 가장 가까운 비행기를 흐리게 지도에 같이 그림. 목업의 "나 → 비행기" 점선은 비행기가 움직여서 선 끝이 어긋나므로 그리지 않음.
- 확대/축소 버튼은 데스크톱(768px 이상)에서만. 폰은 두 손가락 확대.
- 카드 버튼 줄은 MVP에서 "하늘 모드" 하나. "따라가기" 버튼은 따라가기 기능 브랜치에서 `MapPage`의 `sheetActions`로 붙임.
- 새 UI 파일은 `components/mapUi/`에 둠 (지도 위에 올리는 UI). 지도 레이어(Leaflet)는 기존대로 `components/map/`.
- 프로덕션 빌드에서 JS 묶음이 500KB를 넘는다는 경고가 나옴(mqtt.js와 Leaflet이 대부분, gzip 220KB). 기능에는 문제가 없어 그대로 둠.

2. **반경 30km로 넓혔을 때 가장자리 데이터.** 서버는 격자 중심에서 31km를 받아 오는데, 내 위치는 격자 중심에서 최대 약 7km 떨어질 수 있습니다. 그래서 30km 원의 한쪽 가장자리 몇 km에는 비행기가 있어도 안 보일 수 있습니다. 20km에서는 문제가 없습니다(최대 27km < 31km). 30km에서도 완전하게 하려면 서버 조회 반경을 21해리(약 39km)로 늘려야 하는데, 이는 확정된 결정(17해리) 변경이라 바꾸지 않았습니다.
3. **실제 폰에서 확인.** 브라우저 창 크기를 폰(375×812)과 데스크톱(1280×800)으로 바꿔 확인했지만, 실제 iPhone/Android의 안전 영역(노치, 홈 바)과 위치 권한 흐름은 확인하지 못했습니다.


브라우저에서 상태 화면을 강제로 보려면 개발자 도구 콘솔에서 스토어를 바꾸면 됩니다(개발 서버에서만).

```js
const { useFlightsStore } = await import('/src/store/flights.ts');
useFlightsStore.setState({ connection: 'reconnecting' });   // 재연결 중
useFlightsStore.setState({ connection: 'live', sourceStatus: 'degraded' }); // 데이터 지연
```

파일을 고친 뒤(HMR) 이 import가 앱과 다른 모듈을 가리킬 수 있으니, 새로고침한 직후에 실행하세요.
