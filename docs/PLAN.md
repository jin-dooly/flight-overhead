# 내 머리 위 비행기 기획서

Nov 8, 2026 · @이진이

## 개요

내 위치 상공(반경 20km)을 지나는 비행기를 지도 위에 실시간으로 보여주고, 폰을 하늘로 들면 그 방향의 비행기를 알려주는 웹 서비스입니다. 목표는 하루 안에 배포 가능한 MVP입니다.

- **배경**: "방금 지나간 비행기 어디서 왔지?"라는 일상적인 궁금증을 공개 ADS-B 데이터로 바로 답합니다.
- **대상**: 하늘을 올려다보다 비행기가 궁금해진 누구나. 설치 없이 링크로 바로 열립니다.
- **포트폴리오에서 보여줄 것**: 지도 SDK 위 다중 객체 실시간 렌더링, 서버 폴링 후 MQTT 토픽 발행, 끊김 없는 보간 애니메이션, 데이터 소스 장애 시 자동 전환
- **서비스 이름**: 영어 `flight-overhead`, 한글 "내 머리 위 비행기" (2026-11-08 확정)

## 핵심 기능과 범위

MVP는 지도 모드 하나를 완성하는 것이고, 하늘 모드는 시간이 남을 때 붙입니다.

**MVP (필수)**

1. 반경 내 비행기를 지도에 표시: 위치, 진행 방향대로 회전한 아이콘, 편명 라벨
2. 실시간 갱신과 보간 애니메이션: 갱신 사이에도 비행기가 부드럽게 이동
3. 비행기 선택 시 상세 카드: 편명, 고도, 속도, 방향, 나와의 거리
4. 위치: 처음 들어오면 바로 내 위치를 요청. 권한이 없거나 실패하면 인천공항(기본 위치). "내 위치로 보기" 버튼은 지도를 다시 내 위치로 옮기거나 권한을 다시 요청할 때 씀
5. 반경 원(10km, 20km)과 현재 비행기 대수 표시
6. 연결 상태 표시: 실시간 / 재연결 중 / 데이터 지연

**추가 (시간이 남으면, 우선순위 순)**

1. 따라가기: 비행기 하나를 골라 지도 가운데에 고정하고, 착륙하거나 신호가 끊길 때까지 같이 이동 (MVP 배포 직후 1순위)
2. 하늘 모드: 폰 방향에 맞춰 비행기 표시
3. 지나온 경로 꼬리(최근 몇 분)
4. 고도별 아이콘 색상

**하지 않을 것**

- 로그인, 알림, 네이티브 앱
- 과거 이력 저장과 재생
- 출발지/도착지 표시: ADS-B 위치 데이터에는 노선 정보가 없어서, 별도 데이터 확인 전까지 제외 (데모 화면의 "제주 → 김포"는 가짜 값)

## 화면 구성

모바일 세로 화면을 기준으로 설계하고, 데스크탱에서는 같은 화면을 넓게 보여줍니다.

**지도 모드 (대표 화면)**

- 상단 바: 현재 위치 칩, "반경 20km · N대" 칩, 연결 상태 점
- 지도: 내 위치 점, 반경 원 2개(10km, 20km), 비행기 아이콘과 편명
- 하단 카드: 선택한 비행기 상세. 선택 전에는 가장 가까운 비행기를 기본으로 보여줌
- 버튼: 내 위치로 보기, 하늘 모드로 보기

**하늘 모드 (추가 기능)**

- 상단 나침반 띠와 현재 방향 표시
- 비행기 배치: 좌우 = 방위각, 위아래 = 올려다보는 각도(고도와 거리로 계산)
- 가운데 조준 원, 맞춘 비행기 정보를 하단에 표시
- 진입 시 센서 권한 요청 화면 (iOS는 버튼을 눌러야 권한 요청 가능)

**상태별 화면**

| 상태 | 화면에 보여줄 것 |
| --- | --- |
| 위치 확인 중 | 지도는 기본 위치로 그리되 반경 원과 내 위치 점은 숨기고, "내 위치를 확인하는 중" 안내 |
| 위치 권한 거부 | 인천공항 기준으로 계속 보여주고, 상단에 "기본 위치로 보는 중" 안내와 다시 시도 버튼 |
| 반경 내 비행기 0대 | "지금 머리 위에는 비행기가 없어요" + 가장 가까운 비행기까지의 거리, 반경 넓히기 버튼 |
| 서버 연결 끊김 | 마지막 위치를 흐릿하게 유지, "다시 연결하는 중" 표시 |
| 데이터 소스 지연 | "데이터가 N초 전 기준" 표시 |
| 하늘 모드 미지원 기기 | 데스크톱 등 센서가 없으면 "폰에서 열어주세요" 안내 |
| 하늘 모드 센서 권한 거부·센서 없음 | 끌어서 둘러보기로 전환, 위에 이유와 켜는 방법, 다시 시도 |
| 하늘 모드에서 폰을 가로로 돌림 | "폰을 세로로 들어 주세요" 안내 |

## 데이터와 실시간 구조

서버가 공개 API를 주기적으로 호출하고, 같은 지역을 보는 사용자들이 구독한 MQTT 토픽에 한 번에 발행합니다. 브라우저는 API를 직접 부르지 않습니다(CORS 미지원, 호출량 절약).

> (구조도) 데이터 흐름 · 소스 2개, 서버, 브라우저, 지도

메인 소스(adsb.lol)가 실패하면 점선처럼 예비 소스(adsb.fi)로 넘어가고, 브라우저는 받은 스냅샷 사이를 보간해 지도 마커를 직접 움직입니다.

**데이터 소스** (둘 다 키 없음, 비상업 용도, User-Agent 지정, 2026-11-08 송파구·인천 기준 호출 확인)

| 역할 | 소스 | 요청 형식 | 비행기 목록 키 |
| --- | --- | --- | --- |
| 메인 | adsb.lol | `api.adsb.lol/v2/lat/{lat}/lon/{lon}/dist/{nm}` | `ac` |
| 예비 | adsb.fi | `opendata.adsb.fi/api/v2/lat/{lat}/lon/{lon}/dist/{nm}` | `aircraft` (기체 ID 조회는 `ac`) |

adsb.fi는 공개 API를 "1초에 1번"으로 제한하고, 출처 표기와 홈페이지 링크를 요구함(비상업 용도). adsb.lol은 제한 기준을 공개하지 않음("부하에 따라 바뀜").

**서버 흐름**

1. 브라우저가 내 위치를 0.1도 격자로 반올림해 그 격자의 토픽을 구독 (예: `flights/37.5/127.1`). 정확한 위치는 서버에도 외부 API에도 보내지 않음
2. Express 서버에 내장한 MQTT 브로커(Aedes)가 구독 이벤트를 알려주면, 구독자가 있는 격자만 5초 간격으로 반경 21해리(약 39km)의 비행기를 발행. 구독자가 없어지면 폴링 중지
   - 한반도 안 격자는 격자마다 외부 API를 부르지 않고, **지역(중심 36.5, 127.5, 반경 250해리)을 통째로 한 번 조회**해서 각 격자가 그 결과를 나눠 씀. 외부 요청 수가 사용자 수와 상관없이 5초에 약 1번
   - 한반도 밖 격자는 그 격자를 직접 조회
   - 실제로 외부에 나가는 요청(지역 조회, 한반도 밖 격자 조회, 따라가기 조회)만 시작 사이에 최소 1.1초 간격 (adsb.fi 제한, adsb.lol 호출 제한 여유). 지역 결과를 다시 쓰는 격자는 기다리지 않음
3. 응답을 공통 모델(`Aircraft`)로 정규화해 격자 토픽에 **retained 메시지**로 발행. 새 구독자는 구독 즉시 마지막 스냅샷을 받음
4. adsb.lol이 실패하면 adsb.fi로 전환, 둘 다 실패하면 간격을 늘려 재시도하고 `status/source` 토픽에 지연 상태를 발행
5. 브라우저 연결은 구독만 허용해, 누구도 토픽에 임의로 발행할 수 없게 막음

**MQTT 토픽**

| 토픽 | 발행 / 구독 | 내용 |
| --- | --- | --- |
| `flights/{lat}/{lon}` | 서버 발행, 브라우저 구독 | 격자의 `Snapshot` (retained) |
| `status/source` | 서버 발행, 브라우저 구독 | 정상 / 예비 소스 사용 중 / 지연 (retained) |

연결 상태(실시간 / 재연결 중)는 mqtt.js의 연결, 재연결, 오프라인 이벤트로 판단합니다.

**데이터 모델**

```ts
type Aircraft = {
  hex: string        // 기체 고유 ID, 마커 key
  callsign?: string  // 편명 (없을 수 있음)
  lat: number
  lon: number
  altFt?: number     // 기압 고도, 지상이면 없음
  speedKt?: number   // 대지 속도
  trackDeg?: number  // 진행 방향 0~360
  trackRateDegS?: number  // 선회율(초당 도, +는 오른쪽). 일부 기체만 보냄
  seenAt: number     // 위치를 받은 시각(ms)
}

type Snapshot = {
  aircraft: Aircraft[]
  source: 'adsb.lol' | 'adsb.fi'
  fetchedAt: number
}
```

**클라이언트 처리**

- 거리 계산(하버사인)으로 반경 20km 안만 표시하고, 가장 가까운 비행기를 계산
- **보간**: 마지막 위치에 속도와 방향(선회율이 있으면 원호, 최대 30초)을 곱해 매 프레임 현재 위치를 예측. 새 데이터가 오면 표시 위치에서 새 예측 위치로 1초에 걸쳐 수렴시켜 순간이동을 없앰
- **렌더링**: 매 프레임 React state를 바꾸지 않고, `requestAnimationFrame`에서 Leaflet 마커 위치를 직접 갱신. Zustand에는 수신한 스냅샷과 선택 상태만 저장
- 30초 동안 안 보인 비행기는 흐려지게 했다가 제거

## 기술 스택과 배포

오목 프로젝트의 모노레포 구조를 재사용해 세팅 시간을 줄입니다.

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| 프론트엔드 | React, TypeScript, Vite | 주력 스택, 빠른 개발 서버 |
| 지도 | Leaflet (react-leaflet) + OpenStreetMap 타일 | 키 발급 없음, 마커 회전과 직접 제어가 자유로움 |
| 상태관리 | Zustand | 스냅샷, 선택, 연결 상태만 가볍게 관리 |
| 실시간 | MQTT over WebSocket (mqtt.js) | 격자별 토픽 구독, retained 메시지, 자동 재연결, 클레빌 우대사항 |
| 서버 | Express + Aedes 1.2.0 (내장 MQTT 브로커) | 설정이 가볍고, 외부 브로커 없이 같은 서버에서 운영 |
| 모노레포 | Turborepo, 공통 타입 패키지 | 서버와 클라이언트가 `Aircraft` 타입과 토픽 이름을 공유 |
| 테스트 | Vitest | 정규화, 거리 계산, 보간, 소스 전환 순수 함수 |
| 배포 | 프론트 Vercel, 서버는 상시 실행 호스팅 | Vercel 서버리스는 소켓 연결을 유지할 수 없음 |

- 서버 호스팅: Render 무료 플랜 (오목 백엔드와 같은 방식, 2026-11-08 확정). 15분쯤 접속이 없으면 서버가 잠들어 첫 접속이 최대 1분 가까이 느릴 수 있음
- 출처 표기: 지도 구석에 OpenStreetMap, 데이터 출처로 adsb.lol / adsb.fi 표기(각 홈페이지 링크 포함)
- 하늘 모드는 HTTPS에서만 센서와 위치 API가 동작하므로, 배포 환경에서 확인

## 따라가기 설계 (MVP 배포 뒤 작업)

- **토픽:** `aircraft/{hex}` (retained). 서버는 구독자가 있는 기체만 **5초 간격**으로 adsb.lol `/v2/hex/{hex}`를 조회(예비 adsb.fi `/api/v2/hex/{hex}`). 같은 기체를 여러 명이 따라가도 조회는 하나
- **재사용:** 격자 폴러의 구독 수 추적, 예비 전환, 백오프, retained 발행을 그대로 씀
- **지상 기체:** 격자 토픽과 달리 버리지 않고 지상 여부를 함께 보내서 "착륙했어요"를 보여 줌
- **종료 상태:** 착륙, 신호 끊김(3분 이상 미수신 시 마지막 위치 표시. 그동안은 예측 경로로 계속 움직임), 사용자가 끝내기
- **화면:** 지도 끌기를 끄고, 확대·축소는 비행기 중심으로만. 보간 루프에서 매 프레임 지도 중심을 비행기 예상 위치로 옮김
- **남용 방지:** 연결 하나당 따라가기 1개, 서버 전체 동시 따라가기 수 제한
- **확인 필요:** adsb.fi의 기체 ID 조회 지원 여부(예비 소스), adsb.lol `/api/0/routeset`으로 출발·도착 공항을 보여 줄 수 있는지(정확도 확인 전까지 표시하지 않음)

### 4. 서버 상세 명세

**공통 타입 (`packages/shared`)**: 기획서 "데이터 모델"의 `Aircraft`, `Snapshot`을 그대로 쓰고, 아래를 추가합니다.

```ts
type SourceStatus = 'ok' | 'fallback' | 'degraded'
const toGrid = (lat: number, lon: number) => ({ lat: round1(lat), lon: round1(lon) })
const snapshotTopic = (lat: number, lon: number) => `flights/${lat.toFixed(1)}/${lon.toFixed(1)}`
const parseSnapshotTopic = (topic: string) => { lat, lon } | null  // 형식이 틀리거나 범위 밖이면 null
const STATUS_TOPIC = 'status/source'
```

**정규화 규칙 (두 소스 공통)**

- `lat`이나 `lon`이 없는 항목은 버림
- `alt_baro`가 문자열 `"ground"`인 항목(지상 기체)은 버림
- `flight`는 앞뒤 공백 제거, 빈 문자열이면 `callsign` 없음
- 필드 매핑: `hex` → `hex`, `alt_baro` → `altFt`, `gs` → `speedKt`, `track` → `trackDeg`
- `seenAt`: 응답에 `seen_pos`(초)가 있으면 `현재 시각 - seen_pos × 1000`, 없으면 현재 시각

**어댑터와 예비 전환**

- 각 소스는 `fetchAircraft(lat, lon, radiusNm): Promise<Aircraft[]>` 같은 형태의 어댑터로 분리
- adsb.lol 실패(네트워크 오류, 타임아웃, 2xx가 아닌 응답, JSON 파싱 실패) 시 같은 요청을 adsb.fi로 재시도
- 결과에 따라 상태 결정: adsb.lol 성공 `ok`, adsb.fi 성공 `fallback`, 둘 다 실패 `degraded`. 상태가 바뀔 때만 상태 토픽에 발행

**브로커 권한**

- 클라이언트의 발행은 전부 거절. 서버 내부에서 브로커로 직접 발행하는 것만 허용
- 클라이언트 구독은 `flights/{lat}/{lon}` 형식(파싱 성공)과 `status/source`만 허용, 나머지 거절

**폴러**

- 브로커의 구독, 구독 해제, 클라이언트 연결 종료 이벤트로 격자 토픽별 구독자 수를 관리
- 구독자가 1명 이상이 되면 해당 격자의 폴링 시작(즉시 1회 조회 후 간격대로), 0명이 되면 중지
- 같은 격자를 여러 클라이언트가 구독해도 폴링은 격자당 하나
- 조회가 끝나면 `Snapshot`을 retained로 발행
- 동시에 폴링하는 격자가 많아도 외부 API에 몰아서 요청하지 않도록, 격자 간 요청 시작 시각을 분산

**HTTP**

- `GET /health` → `{ status: 'ok', activeGrids: number, source: SourceStatus }`
- 환경 변수: `PORT`(기본 4000), `POLL_INTERVAL_MS`(기본 5000), `RADIUS_NM`(기본 17), `USER_AGENT`. `.env.example` 작성

### 5. 테스트와 확인

- Vitest 단위 테스트 (외부 API는 모두 모킹, 테스트에서 실제 API 호출 금지)
  - 정규화: adsb.lol, adsb.fi 응답 샘플 각각, 지상 기체와 위치 없는 항목 제외
  - 격자: 반올림, 토픽 생성과 파싱, 잘못된 토픽 거절

### 7. 작업 규칙

- 사용자에게 질문하지 않는다. 대신 판단의 크기에 따라 처리한다
  - 작은 결정(파일 이름, 함수 구조, 패키지 버전 등)은 기획서 취지에 맞게 결정하고 HANDOFF.md의 "내린 결정"에 한 줄로 기록
  - 기획서의 범위나 확정된 결정을 바꿔야 하는 문제는 결정하지 말고, 해당 작업을 멈추고 HANDOFF.md의 "확인 필요"에 기록한 뒤 다음 작업으로 넘어감
- Aedes 사용법은 반드시 1.2.0 공식 README와 패키지에 포함된 타입 정의를 확인한 뒤 작성. 추측으로 작성하지 않음
- 단계마다 테스트와 타입 체크가 통과한 뒤에 커밋. 커밋 메시지는 `feat(server): ...`, `chore: ...`, `test(server): ...` 형식
- 같은 문제로 오래 막히면(같은 오류를 서로 다른 방법으로 3번 시도해도 실패) 그 단계를 멈추고 기록한 뒤 다음 단계 진행
- 비밀값, 개인 정보, 실제 사용자 위치를 코드나 로그에 남기지 않음
- 사용자가 아침에 코드를 이해할 수 있도록, 핵심 판단이 들어간 코드(예비 전환, 백오프, 구독 수 추적)에는 왜 그렇게 했는지 짧은 주석을 남김
